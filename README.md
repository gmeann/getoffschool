# 퇴근길 학교 (가칭)

초등 선생님을 위한 웹 기반 3D 쉼터예요. 로그인 없이 들어와서, 노을 진 운동장을 천천히 걸으며 쉬어 가는 공간입니다.

- Vite + React + TypeScript
- three, @react-three/fiber, @react-three/drei
- 서버·DB·외부 모델/텍스처 파일 없음. 모든 물체는 기본 도형으로 코드에서 만듭니다.
  (글꼴만 Pretendard(본문)·Gaegu(손글씨·분필) 웹폰트를 CDN에서 불러오고, 실패하면 시스템 글꼴을 씁니다.)

## 실행 방법

Node.js 20 이상이 필요해요. 레포를 받은 폴더에서 실행합니다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173` 을 열면 됩니다.

### 폰으로 접속해 보기

PC와 폰이 **같은 와이파이**에 있어야 해요.

```bash
npm run dev -- --host
```

터미널에 나오는 `Network: http://192.168.x.x:5173/` 주소를 폰 브라우저에 입력하세요.

### 빌드 / 미리보기

```bash
npm run build
```

```bash
npm run preview
```

## 조작

- 바닥을 클릭(폰은 탭)하면 캐릭터가 그 지점으로 걸어가요.
- **뛰기**: 트랙을 따라 계속 달려요. 다시 누르거나(멈추기) 바닥을 클릭하면 멈춰요.
- **앉기**: 가장 가까운 벤치(6개)나 가운데 잔디밭으로 가서 앉아요. 잔디밭 안에 있으면 그 자리에 바로 앉아요. 앉아 있는 동안 카메라가 조금 가까이 와요. 다시 누르면 일어나요.
- **하늘 보기**: 카메라가 천천히 하늘을 올려다봐요. 다시 누르거나 움직이면 원래대로 돌아와요.
- PC에서는 마우스 휠로 확대/축소할 수 있어요. 카메라 회전은 일부러 넣지 않았어요.

## 운동장 이야기

- **시간대별 하늘**: 기기 시각에 따라 오전·낮·저녁(노을)·밤으로 하늘과 조명이 바뀌어요. 시간대 사이는 부드럽게 이어져요.
- **산책하는 선생님**: 파스텔 옷을 입은 선생님 6~8명이 설렁설렁 트랙을 걷거나 뛰고, 1~2명은 벤치에 앉아 있어요. 가까이 가면 말을 걸어요.
- **걸음 카운터**: 운동장에서 이동한 거리만 트랙 한 바퀴(약 70m) 기준으로 "오늘 나는 N바퀴"로 보여 줘요. 한 바퀴마다 "한 바퀴 완주!", 10바퀴를 채우면 "운동장 10바퀴" 칭호가 생겨요.
  - 저장 위치: 브라우저 localStorage (`getoffschool:meters:날짜`, `getoffschool:titles`). 서버에는 아무것도 보내지 않아요.

## 공간 이동 (3단계)

- 공간은 한 번에 하나만 불러와요: `playground`(운동장), `office`(교무실), `classroom`(교실), `lab`(연구실). 4개 공간이 모두 열려 있어요.
- 공간 정의(이름, 배경색, 입장 위치, 문 위치, 하단 버튼)는 `src/data/scenes.ts` 한 곳에서 관리해요.
- 운동장 북쪽 학교 건물의 문(교무실·교실·연구실)을 누르면 문 앞까지 걸어가서 들어가요.
- 좌상단 "퇴근길 학교 | 공간이름"을 누르면 공간 목록이 펼쳐져요.
- 바닥이나 물건을 누르면 가구를 돌아서 걸어가요 (사각형 가구 모서리를 경유하는 간단한 길찾기).

### 교무실

- NPC 3명(교무실무원, 교무부장님, 교감선생님)을 누르면 앞까지 걸어가서 대화창이 열려요.
- **간식 받기**: NPC마다 하루에 한 번(기기 날짜 자정 기준). 간식 20종, 희귀도 흔함 70%·특별함 25%·귀함 5%.
- **도감**: 모은 간식과 개수를 20칸 격자로 보여 줘요. **인사하기**: 가까운 NPC에게 고개 숙여 인사해요.
- 저장 위치: localStorage `getoffschool:snacks`(도감), `getoffschool:snackGiven`(오늘 받은 NPC)

### 교실 (4단계)

- 앞쪽 칠판에 **오늘의 한마디**(날짜마다 30개 중 하나), 교탁, 학생 책상 16세트, 사물함·게시판, 열린 창문, 내 업무 책상과 파쇄기.
- **업무 날리기**: 내 책상 위 기본 서류 20장. 날린 서류는 바로 다시 채워지지 않고, 날짜가 바뀌면(로컬 자정) 다시 20장이 쌓여요. "날리기" 버튼이나 서류 더미를 누르면 맨 위 한 장이 사라져요.
  - **서류 추가**: 마음에 걸리는 일을 직접 적어(14자까지, 하루 20장까지) 더미 맨 위에 올릴 수 있어요. 내가 올린 서류부터 날아가요. 다 날린 뒤에도 추가하면 다시 날릴 수 있어요.
- **앉기**: 학생 의자 16개나 내 업무 의자에 앉을 수 있어요.
  - 방식 4가지 + 아무거나: ✈️ 종이비행기(열린 창문 밖으로) · 🗂️ 파쇄기(띠 조각) · 🧽 칠판지우개(분필 글씨 슥슥) · 🎈 업무 풍선(팡! 색종이)
  - 고른 방식은 저장돼요. 연타하면 연속으로 날아가요. 한 장 연출은 약 1.25초.
  - 다 날리면 "오늘 업무 끝! 퇴근 준비 완료" + 칭호 **퇴근 준비 완료**.
- **카운터**: 상단 "오늘 날린 업무 N장 · 누적 M장". 읽고 쓰는 코드는 `src/services/counterService.ts` 한 곳뿐이에요.
  - 인터페이스: `getToday()`, `getTotal()`, `getSnapshot()`, `addOne()`, `subscribe()`, `reset()`
  - 지금은 localStorage 구현이고, 나중에 서버 공유 값으로 바꿀 때는 같은 인터페이스의 구현을 만들어 파일 맨 아래 `counterService` 한 줄만 바꾸면 돼요.
- 저장 위치: `getoffschool:pile:날짜`(남은 기본 서류), `getoffschool:custom:날짜`(내가 올린 서류), `getoffschool:flung:날짜`·`getoffschool:flungTotal`(카운터), `getoffschool:flingMethod`(방식)

### 벤치 "마음 띄우기" (5.5단계, 혼자 털기)

- 운동장 벤치(또는 잔디)에 앉으면 하단 버튼이 "마음 띄우기 / 일어나기"로 바뀌어요.
- 속마음을 100자 이내로 쓰고 "띄우기"를 누르면, 글이 구름이 되어 머리 위에 1.5초 보였다가 노을 하늘로 떠올라 사라져요(약 5초, 빛 입자 최대 30개).
- **쓴 글은 어디에도 저장하지 않아요.** 화면 메모리에만 잠깐 있다가 연출이 끝나면 지워져요. localStorage·sessionStorage·IndexedDB·쿠키·서버·콘솔 모두 사용하지 않고, 입력창은 자동완성·맞춤법 검사를 끕니다.
  - 저장하는 것은 "오늘 마음을 띄웠는지" 날짜 하나(`getoffschool:mind:floatedOn`)뿐. 이날은 교무실 NPC가 위로 대사(NPC별 5개)를 섞어 말해요.
- 전화번호·이메일 형식이 보이면 막지 않고 부드럽게 안내만 해요.
- 자기 위해를 암시하는 표현이 보이면 연출 뒤 따뜻한 안내 창(상담전화)을 보여 줘요. 감지 결과도 기록하지 않아요.
  - 감지 목록: `src/data/crisisWords.ts`
  - 문구·버튼 이름·상담전화 번호와 운영 정보: `src/data/mindFloat.ts` (`MIND_TEXT`, `CRISIS_CONTACT`, `CRISIS_TEXT`)

### 연구실 (5단계)

- 책장, 큰 작업 테이블(노트북·머그컵), 러그, 화분 + 상호작용 오브젝트 3개. 가까이 가면 테두리가 반짝이고 "눌러서 열기"가 떠요.
  - 📌 **메모보드**: 수업 아이디어와 꿀팁 · 반응 "써볼게요" · 포스트잇 색 4가지
  - 🧊 **냉장고**: 간식, 선물, 맛집 추천 · 반응 "맛있겠다" · 추천 이유 한 줄
  - 🖍️ **칠판**: 오늘의 한마디 · 반응 "나도 그래요" · 분필 글씨체
- 오브젝트나 하단 버튼을 누르면 앞까지 걸어가서 하단 시트 패널이 열려요. 최신순/공감 많은 순, 반응은 한 글에 한 번(다시 누르면 취소).
- **글 남기기 규칙**: 60자 이하(줄바꿈 없음), 완전 익명(무작위 이름 또는 "익명의 선생님"), 개인정보 안내 고정, 금지어·전화번호·이메일 차단(`src/data/bannedWords.ts`), 올린 뒤 30초 동안 연속 입력 제한, 내 글만 삭제. 글은 텍스트로만 그려요(HTML 해석 없음).
- 시드 글: 게시판마다 15개 (`src/data/boards.ts`), 반응 수 3~40.
- **데이터 접근**: 글·반응·삭제는 `src/services/boardService.ts` 하나로만 해요. 화면은 localStorage 를 직접 다루지 않아요.
  - 인터페이스: `getPosts(board, sort)`, `addPost(board, post)`, `toggleReaction(board, postId)`, `deleteMyPost(board, postId)`, `getCooldownRemaining()` — 모두 Promise
  - 6단계에서 같은 인터페이스의 Firebase 구현을 만들어 파일 맨 아래 `boardService` 한 줄만 바꾸면 돼요.
- 저장 위치: `getoffschool:board:posts:게시판`(내 글), `getoffschool:board:reacted`(내 반응), `getoffschool:board:lastPostAt`(연속 입력 제한), `getoffschool:guide:lab`(첫 안내)

## 6단계: Firebase 공유 (게시판 · 마음 나누기 · 공유 카운터)

### 설정
1. `.env.example` 을 `.env.local` 로 복사하고 Firebase 웹 앱 설정 값을 채웁니다. `.env.local` 은 git 에 올라가지 않아요.
2. 값이 없거나 연결에 실패하면 앱은 **"지금은 혼자 보는 모드예요"** 안내와 함께 시드 글 + 로컬 저장으로 계속 동작해요.
3. 개발용: 주소에 `?offline=1` 을 붙이면 Firebase 를 아예 쓰지 않아요.
4. Analytics(measurementId)는 쓰지 않아요 (마음 띄우기 원칙: 분석 도구 금지).

### 데이터 구조
| 경로 | 내용 |
| --- | --- |
| `posts/{id}` | board(`memo`/`fridge`/`blackboard`), text(1~60자), color(메모보드), reason(냉장고), nick, uid, createdAt(서버 시각), reactionCount, reportCount, hidden |
| `posts/{id}/reactions/{uid}` | 사용자당 반응 1회 보장 (지우면 반응 취소 = -1) |
| `posts/{id}/reports/{uid}` | 사용자당 신고 1회, 3건이면 hidden=true |
| `hearts/{id}` | 마음 나누기: text(1~100자), nick, uid, createdAt, pat·thanks·together, reportCount, hidden |
| `hearts/{id}/reactions/{uid}` | { kind } — 한 글에 반응 하나 (바꾸면 취소 후 새로) |
| `hearts/{id}/reports/{uid}` | 사용자당 신고 1회 |
| `users/{uid}` | { lastWriteAt } — 글쓰기 30초 도배 방지 (글과 같은 batch 로만 갱신) |
| `daily/{YYYY-MM-DD}` | { flung, laps, visitors } — 날짜별 카운터 (한 문서에 쓰기가 몰리지 않게 날짜로 나눔) |
| `counters/total` | { flung } — 누적 날린 업무 |
| `visits/{YYYY-MM-DD}/users/{uid}` | 오늘 방문 기록 (사용자당 하루 1회, 만들 때만 visitors +1) |

- 시드 글은 DB 에 넣지 않고 화면에서 합쳐요. 한 게시판에 최대 30개를 보여 주는데, 진짜 글이 늘면 시드는 뒤로 밀려 사라져요. 시드 글은 신고·삭제 대상이 아니고, 시드 글 반응은 이 기기에만 저장돼요.
- 제안 구조에서 바꾼 점: ① 반응 **취소(-1)** 를 허용 (5단계 UI 의 "다시 누르면 취소"를 유지하려고, 내 반응 문서를 지울 때만 -1 가능) ② 카운터를 `daily/{날짜}` 와 `counters/total` 로 나눔 ③ 목록 조회 규칙에 `hidden == false` 를 강제해서 숨김 글이 쿼리로 내려오지 않게 함.

### 보안 규칙 요약 (`firestore.rules`)
- 모든 읽기·쓰기는 로그인(익명 포함)한 사용자만. 정의하지 않은 경로는 전부 거절.
- 글/마음 생성: 허용 필드만, 글자 수·줄바꿈 검사, uid = 요청자, 반응·신고 수 0, hidden=false, createdAt = 서버 시각, 같은 요청에서 `users/{uid}.lastWriteAt` 갱신(30초 이내면 거절).
- 수정은 두 경우만: 반응 문서 생성/삭제와 함께 개수 ±1, 신고 문서 생성과 함께 reportCount+1 (3 이상이면 hidden=true 를 반드시 같이). 그 밖의 필드 변경은 거절.
- 삭제는 글쓴이(uid 일치)만.
- 카운터: 한 번에 0~50 증가만 (감소·임의 값 설정 불가), 방문자 수는 오늘 방문 기록을 처음 만들 때만 +1.

### 규칙으로 막을 수 없는 것 (남은 위험)
- **익명 계정을 계속 새로 만드는 도배**: 계정마다 30초 제한이라, 새 계정을 반복해서 만들면 우회돼요. → App Check(reCAPTCHA) 도입으로 완화 가능.
- **금지어·개인정보 필터는 클라이언트에만** 있어요. 앱을 거치지 않고 직접 API 를 부르면 우회돼요. 규칙에는 복잡한 금지어 검사를 넣기 어려워서, 신고 3건 자동 숨김이 마지막 방어선이에요. → 나중에 Cloud Functions 로 서버 검사 추가 권장.
- **신고 악용**: 여러 익명 계정으로 멀쩡한 글을 3번 신고하면 숨겨져요. 숨김 글을 되살리는 관리자 화면이 아직 없어요 (Firebase 콘솔에서 hidden 을 false 로 바꿀 수 있음).
- **카운터 부풀리기**: 한 번에 최대 50씩이지만, 반복 호출로 숫자를 키울 수는 있어요. 날짜 문서 이름이 오늘인지도 규칙에서 검사하지 않아요.
- 글자 수는 규칙의 문자열 길이 기준이라 이모지처럼 특수한 문자는 화면 글자 수와 조금 다를 수 있어요.

### 사용량 (장면별 예상)
| 시점 | 읽기 | 쓰기 |
| --- | --- | --- |
| 앱 시작 (하루 첫 방문) | 규칙 검사 1~2 | 2 (방문 기록 + 방문자 수) |
| 아무 장면에 들어갈 때 | 2 (오늘 카운터 + 누적) | 0 |
| 운동장 들어갈 때 | + 최대 12 (나눈 마음 구름, 없으면 1) | 0 |
| 연구실 게시판 열기 | 게시판·정렬마다 최대 30 (1분 안에 다시 열면 0) | 0 |
| 글 남기기 / 마음 나누기 | 규칙 검사 1~2 | 2 (글 + 도배 방지 문서) |
| 반응 / 반응 취소 | 규칙 검사 2 | 2 (반응 문서 + 개수) |
| 신고 | 0~1 (+규칙 검사) | 2 |
| 업무 날리기·운동장 바퀴 | 0 | 모았다가 10초마다 최대 2 (날린 게 있을 때만) |
- 실시간 구독(onSnapshot)은 쓰지 않아요. 한 사람이 연구실 게시판 3개를 모두 열어 보는 방문 한 번이 대략 읽기 100회 안팎이에요.
- 무료 요금제(Spark)는 하루 읽기 5만·쓰기 2만 회예요. 한도를 넘거나 서버가 응답하지 않으면 앱은 혼자 보는 모드로 바뀌고(한도 초과는 10분, 그 밖의 오류는 45초 뒤 다시 시도), 화면은 멈추지 않아요.

### 샤딩이 필요해지는 기준
한 문서는 초당 1회 정도의 지속 쓰기가 안전한 한계예요. 지금은 활동 중인 사람마다 10초에 한 번만 `daily/{날짜}` 를 쓰므로, **동시에 업무를 날리거나 운동장을 도는 사람이 10명을 꾸준히 넘거나**, 쓰기가 "contention/aborted" 오류로 실패하기 시작하면 `daily/{날짜}/shards/{0~9}` 처럼 나눠 쓰고 읽을 때 합치세요.

### 사용량이 늘면 할 일
1. **App Check** 도입 (reCAPTCHA Enterprise) — 앱 밖에서의 호출·계정 반복 생성 도배 완화
2. **읽기 캐시 강화** — 게시판 캐시 시간을 늘리고, 카운터는 장면 이동마다가 아니라 1~2분에 한 번만 읽기
3. **요금제 변경** — 하루 한도를 자주 넘으면 Blaze(사용량 과금)로 바꾸고 예산 알림 설정
4. **Cloud Functions** — 금지어·개인정보 서버 검사, 신고 알림, 숨김 글 관리

## 7단계: 설정 · 소리 · 관리자 모드

### 설정 (톱니바퀴 버튼, 이 기기에만 저장: `getoffschool:settings`)
- **소리**: 배경음악·효과음 켜기/끄기와 크기. 기본은 꺼짐이고, 한 번 켜면 다음 접속에도 켜진 상태로 기억해요.
  브라우저 정책상 화면을 한 번 눌러야 소리가 시작돼요. 탭이 가려지면 소리를 멈춰요.
- **나**: 이름 다시 뽑기, 글·마음을 나눌 때 기본으로 '익명의 선생님'
- **저사양 모드**: 해상도 1배, 산책하는 선생님 3~4명
- **개인정보 안내**, **이 기기 기록 지우기**(설정만 남기고 모두 지움)
- 상단 스피커 버튼은 배경음악·효과음을 한 번에 켜고 꺼요.

### 소리 (`src/audio/engine.ts`, 음원 파일 없음)
- Web Audio 로 코드에서 직접 만들어요: 느린 화음 패드 + 가끔 울리는 맑은 음 + 잔향.
- 운동장은 바람 소리, 저녁·밤 풀벌레, 오전·낮 새소리. 실내는 조금 더 따뜻하고 드문드문.
- 효과음: 문 열기, 간식 띵, 칭호 팡파르, 한 바퀴, 종이비행기 슝, 파쇄기, 지우개, 풍선 팡, 글 붙이기, 반응, 구름 띄우기, 인사.

### 관리자 모드
1. Firebase 콘솔 → Authentication → 로그인 방법에서 **Google** 을 켜고, 승인된 도메인에 `gmeann.github.io` 가 있는지 확인해요.
2. 사이트 주소 뒤에 `?admin=1` 을 붙여 열고 → 설정 → **Google 계정으로 관리자 로그인**.
3. 처음에는 "아직 관리자로 등록되지 않았어요"와 함께 계정 ID 가 보여요. 복사해서
   Firebase 콘솔 → Firestore → `admins` 컬렉션에 **그 ID 를 문서 ID 로** 문서를 하나 만들어요 (필드는 아무거나, 예: `note: "나"`).
4. 새로고침하면 **관리자 화면**: 신고된 글(숨김 포함) 되살리기·삭제, 오늘 통계(방문자, 날린 업무, 바퀴, 오늘 글·마음 수, 신고 수).
5. 다 쓰면 설정에서 로그아웃하면 다시 익명 사용자로 돌아가요.
- 규칙: `admins/{uid}` 문서가 있고 **익명이 아닌** 계정만 관리자예요. `admins` 문서는 앱에서 만들 수 없어요(콘솔에서만).
  관리자도 글 내용은 바꿀 수 없고, 되살리기(숨김 해제 + 신고 0)와 삭제만 할 수 있어요.
- 되살린 글은 신고 수가 0이 되지만, 이전에 신고한 사람의 신고 기록은 남아서 같은 사람이 다시 신고할 수는 없어요.
- 규칙을 고쳤으니 `firebase deploy --only firestore --project getoffschool` 로 다시 배포해야 해요.

## 8단계: 실시간 함께 있기 (Realtime Database)

같은 공간(운동장·교무실·교실·연구실)에 접속한 선생님의 캐릭터가 실시간으로 보여요.

- 실제 사람의 이름표에는 **초록 점**이 붙어요 (산책하는 선생님 NPC 와 구분). 상단에 **"지금 N명"**(학교 전체 접속 인원)이 보여요.
- 걷기·뛰기·앉기·인사하기 동작이 그대로 보여요. 채팅은 없어요.
- 보내는 것: 이름표 번호(목록 순서, 자유 글자 없음), 위치, 방향, 자세뿐. 움직일 때만 0.5초마다 보내고, 멈춰 있으면 보내지 않아요.
- 탭을 닫거나 네트워크가 끊기면 서버가 내 기록을 자동으로 지워요. 화면을 30초 넘게 가리면 연결을 잠시 끊어요.
- 코드: `src/services/presenceService.ts`(주고받기), `src/components/RemotePlayers.tsx`(그리기)

### 설정
1. Firebase 콘솔 → **Realtime Database** → 데이터베이스 만들기 (위치: **싱가포르 asia-southeast1**, 한국에서 가장 가까움. 서울은 없음) → 잠금 모드
2. **규칙** 탭에 `database.rules.json` 내용을 붙여 넣고 **게시**
3. GitHub 레포 Variables 에 `VITE_FIREBASE_DATABASE_URL` 추가 (값: Realtime Database 화면 위쪽 주소) → Actions 에서 다시 배포
- 주소가 비어 있으면 이 기능만 꺼지고 나머지는 그대로 동작해요.

### 무료 요금제(Spark) 한도
- **동시 접속 100명**까지. 넘으면 그 뒤에 들어온 사람은 다른 사람이 안 보이고 혼자 걷는 것처럼 보여요 (앱은 계속 동작).
- 다운로드 월 10GB. 30명이 같은 공간에서 계속 걸어 다니면 대략 하루 몇 시간 정도 버틸 수 있는 양이에요. 대부분 멈춰 있거나 앉아 있으면 훨씬 여유 있어요.
- 한 공간에 그리는 다른 사람은 최대 30명 (`MAX_OTHERS`).

### 테스트
```bash
npm run test:db      # Realtime Database 보안 규칙 테스트 9개 (에뮬레이터)
```

## 9단계: 접속한 선생님과 인사·반응

정해진 보기만 고르는 방식이라 직접 쓰는 글이 없어요 (금지어 검사·신고 관리가 필요 없음).

- **인사 주고받기**: 초록 점 선생님을 누르면 가까이 걸어가서 꾸벅 인사해요. 상대 화면에 "○○ 선생님이 인사했어요"와 **맞인사** 버튼이 10초 동안 떠요. 맞인사하면 내 화면에 "맞인사했어요" 알림이 와요. 같은 사람에게는 8초에 한 번.
- **반응 보내기**: 오른쪽 아래 😊 버튼 → 이모지 8개 또는 응원 한마디 8개 중 하나를 고르면 내 머리 위에 2.8초 동안 떠요. 같은 공간의 모두가 봐요. 2.5초에 한 번.
- 문구·이모지 목록: `src/data/reactions.ts` (서버에는 번호만 보내요. 순서를 바꾸지 말고 뒤에 추가하세요)
- 서버로 보내는 값: 반응 번호와 보낸 횟수, 인사한 상대의 계정 ID와 횟수. 처음 들어왔을 때는 예전 반응을 다시 보여 주지 않아요.
- 규칙을 고쳤으니 Firebase 콘솔 → Realtime Database → 규칙 탭에 `database.rules.json` 을 다시 붙여 넣고 게시해야 해요.

### 개발용: 시간대 강제로 바꾸기

주소 뒤에 `?time=` 을 붙이면 돼요.

- `http://localhost:5173/?time=morning` (오전)
- `http://localhost:5173/?time=day` (낮)
- `http://localhost:5173/?time=evening` (저녁)
- `http://localhost:5173/?time=night` (밤)
- 숫자도 돼요: `?time=17.5` (오후 5시 30분)

### 개발용: 날짜 바꾸기 / 기록 초기화

- `?date=2026-11-02`: 오늘 날짜를 그 날짜로 강제 (하루 한 번 간식 제한 확인용)
- `?offline=1`: Firebase 를 쓰지 않는 혼자 보는 모드
- `?reset=1`: 이 기기의 기록만 지움 — 도감·간식 기록, 교실 서류 더미(내가 올린 서류 포함), 날린 업무 카운터, 칭호, 연구실 데이터(내 글·반응·첫 안내), 오늘 마음을 띄웠는지 값을 지움 (바퀴 수는 그대로, 지운 뒤 주소에서 `reset` 은 저절로 빠져요)
- 함께 쓸 수도 있어요: `?time=night&date=2026-11-02`

## 배포 (GitHub Pages)

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml` 이 자동으로 빌드해서 GitHub Pages에 올립니다.
배포 주소: **https://gmeann.github.io/getoffschool/**

처음 한 번만 설정이 필요해요.

1. GitHub 레포 → **Settings → Pages**
2. **Build and deployment → Source** 를 **GitHub Actions** 로 선택
3. Actions 탭에서 실패한 실행이 있으면 **Re-run all jobs** (또는 **Run workflow**) 를 누르면 배포됩니다.

### 레포 이름(base 경로) 바꾸기

- 워크플로는 레포 이름을 자동으로 읽어서 `BASE_PATH=/<레포이름>/` 로 빌드해요. 레포 이름을 바꿔도 따로 고칠 것이 없어요.
- 직접 빌드할 때는 `vite.config.ts` 의 `REPO_NAME` 상수를 고치거나, 환경변수로 덮어쓰면 됩니다.

```bash
BASE_PATH=/my-repo/ npm run build
```
